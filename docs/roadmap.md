# Roadmap

This roadmap is intentionally high-level and will change as research
findings come in. Nothing below is a commitment to specific features — it
describes the _process_ the project is following, not a finalized backlog.

## Phase 0 — Engineering foundation (current)

- [x] Initialize the repository with a modern, strict React + TypeScript +
      Vite stack.
- [x] Set up linting (ESLint), formatting (Prettier), and testing
      (Vitest + React Testing Library).
- [x] Ship a polished placeholder landing page explaining the project and
      its discovery phase.
- [x] Set up GitHub Pages deployment so the project is shareable with
      testers and feedback-givers from day one.
- [ ] Gather initial community feedback (see `research.md`).

## Phase 1 — Discovery

- [ ] Collect and synthesize feedback from the Frutiger Aero community on
      unmet needs.
- [ ] Narrow candidate product directions based on that feedback.
- [ ] Write a short product brief for the chosen direction, including what
      it explicitly will _not_ try to be.

## Phase 2 — MVP

- [ ] Design the core interaction(s) for the chosen direction.
- [ ] Implement a minimal, functional version — favoring a small number of
      things that work well over broad, shallow feature coverage.
- [ ] Expand automated test coverage alongside real functionality.

## Phase 3 — Testing & iteration

- [ ] Share the MVP with the community that gave initial feedback.
- [ ] Iterate based on real usage, not assumptions.
- [ ] Revisit architecture decisions if the product direction has shifted
      significantly from the Phase 0 foundation.

## Phase 4 — Release

- [ ] Polish, document, and publish a tagged release.
- [ ] Decide on an ongoing maintenance and contribution model.
